## 2. 总体策略

### 2.1 双版本策略

- **内部版（internal）**
  - 功能与通用版完全一致，不做功能裁剪
  - 增加：内部共享盘更新通道、计算机域控制
- **通用版（general）**
  - 功能与内部版完全一致
  - 更新走 HTTPS 清单，不做域限制

### 2.2 Excel 优先、PDF 收敛

- 主要研发与测试资源投入 Excel：`.xlsx/.xls/.xlsm/.csv`、DLP 加密回退、复杂表头、金额单位、符号口径、大文件
- PDF 保持现有能力不倒退，增加“解析置信度提示”，扫描件作为外部 OCRFlow 导入场景，不投入核心引擎改造

### 2.3 知识库版权与分发原则

- CAS 官方公开法规可内置
- 陈版主等第三方整理资料：按用户决策**先集成到内部知识库**；本项目不计划商用
- 数字签名不作为主要限制：内部版使用自签名/企业证书即可，通用版再按需要评估

## 5. 关于数字签名与版权问题的结论

### 数字签名

- 公开可信的代码签名证书**不强制要求“微软账号”**，但通常向 DigiCert、Sectigo 等 CA 购买 OV/EV 证书；EV 证书需要企业认证，价格更高
- 微软的 Azure Trusted Signing 才需要 Entra ID/微软账号体系，并按月/按签名量收费
- **内部使用**：不必购买公共证书。可以用企业 AD CS 或自签名证书，并通过域策略信任；这足以消除内部部署的主要警告，成本最低
- **通用版对外分发**：建议购买 OV 证书或使用 Azure Trusted Signing，否则 Windows SmartScreen 会提示未知发布者

### 陈版主资料

- 版权不因“内部学习”而自动消失
- 内部小范围学习使用风险较低，但**打包进安装程序并分发给其他人属于复制/传播行为**，风险会上升
- 建议：不放入安装包；仅作为内部知识库的“用户导入内容”，或取得作者授权后再内置
